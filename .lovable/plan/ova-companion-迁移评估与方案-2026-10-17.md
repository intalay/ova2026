# OVA Companion 迁移评估与方案

## 1. 读到的现状
- 代码约 3,800 行：Node 24 服务（`node:sqlite`，自带 HTTP、会话、密码哈希）+ 浏览器原生 ES 模块前端，无第三方依赖。
- 27 张表：用户/会话、组别/球队/赛事、比赛/排名/名单、场馆/停车、公告、配对码（invite_codes + verification_grants）、family_links、player_team_links、关注、通知、导入记录与覆盖率。
- 配对码已在服务端区分：TEAM 码可多人使用、换码即撤销旧码；FAMILY 码每段关系独立、单次使用（uses=0 才能消费），生成前要求球员已通过球队验证。
- 每日 02:00（多伦多）批处理只重检本地快照，不抓取实时数据。

## 2. 功能保留 / 适配
直接复用（逻辑与规则照搬）：
- 配对码规则、家属可见性检查、教练申请审批、关注、通知去重规则
- AES / TIMU / MyTeam / 名单导入解析器（纯数据转换）
- 赛程、成绩、趋势图、日历（当前月+后两个月）、场馆/停车、视频入口的数据规则与“待定”显示
- 对 AES "Finish" 未确认为最终名次的标注

需要适配：
- 数据库：SQLite → Lovable Cloud（Postgres），SQL 方言与事务改写
- 登录：自建密码/会话 → Lovable Cloud 账号；角色放独立角色表
- 接口：自建 HTTP 路由 → 服务端函数，权限检查保留在服务端
- 前端：原生模块 → React 页面，按新 UI 方向重做外观
- 定时批处理：需改为定时任务入口（且当前只重检快照，可先保留为手动“工作人员导入”）

## 3. 当前平台能否运行原后端
不能。预览和发布运行在边缘运行时上，没有 Node 进程、本地文件系统和 `node:sqlite`。

| | A. 保留原后端，另行部署，经 API 连接 | B. 迁移到 Lovable Cloud |
|---|---|---|
| 工作量 | 前端改造即可，但需你方另购/维护一台 Node 主机、持久磁盘、HTTPS、跨域 | 中等：约 10 个服务端模块改写 + 27 张表迁移 |
| 数据风险 | SQLite 单文件需备份方案；预览依赖外部主机在线 | 结构化迁移，有托管备份；现有测试需重写验证 |
| 权限风险 | 原逻辑不变，风险低；但跨域会话 cookie 需额外处理 | 改写时可能出错，需逐条测试覆盖配对码与家属可见性 |
| 在线预览 | 需你方先部署服务器 | 直接可用 |

推荐 B：项目小、无依赖，且你要的是可访问的在线预览；A 需要购买外部服务器（你要求未经确认不购买）。原 184 项测试作为规则清单，迁移后重写成新测试并重新运行，不沿用旧结果。

## 4. 数据分类
- 真实数据：AES/TIMU/MyTeam 历史快照（README 称 1,836 场、422 个 AES 名次）——ZIP 中不含，位于被忽略的 `data/raw/source/`。
- 演示数据：`seed.mjs` 中的虚构账号（admin/staff/coach/player/player2/family@demo.test）与未来赛程，显示时钟固定 2026-10-17 08:00；`data/fixtures/` 三个虚构解析样本。
- 未连接的外部服务：实时赛事数据源、OVA/MRS 写入、官方身份验证、邮件发送、Google Maps（可选）、YouTube Data API（可选）。场馆停车坐标与照片授权仍未确认。

演示与真实数据在界面上继续分开标注（保留原“Source data / Synthetic demo”切换）。演示账号的公开密码不会放进线上环境；改为仅在预览中可用的演示登录，需你确认。

## 5. 需要你提供（之后通过安全表单填写，不要贴到聊天中）
- 真实历史快照文件（如需在线展示真实成绩）——作为上传文件，非密钥
- 可选：Google Maps 浏览器 Key（限制到预览域名）
- 可选：YouTube Data API Key
- 确认：停车信息与场馆照片的授权来源
- 确认：线上预览是否允许演示账号登录
邀请码签名密钥由系统自动生成，无需你提供。

## 6. 实施步骤（确认后执行）
1. 开启 Lovable Cloud；建表 + 角色表 + 行级权限；写入演示种子数据
2. 改写服务端：身份/配对码、赛事、内容、导入、维护
3. 设计系统：高对比、大字号（正文 18px）、清晰焦点框、减少动效支持
4. 先做 Guest 首页和家属首页（关联球员、下一场比赛、最近成绩、Next Venue），再统一赛程、成绩、Explore、场馆、视频、Account、工作人员页面
5. 测试：配对码规则、家属越权访问、日历范围、“待定”显示，并用浏览器逐项走核心流程
6. 报告：已完成 / 未完成 / 模拟部分；不发布、不购买、不接真实用户数据

## 技术细节
- 前端：TanStack Start 路由（/、/schedule、/results、/explore、/venue/$id、/account、/staff）
- 服务端：createServerFn + 身份中间件；家属访问球员私有数据前查询 family_links
- 配对码：FAMILY 消费用单条条件 UPDATE 保证单次使用；TEAM 码保留 max_uses / 轮换撤销
- 每日批处理：先保留为工作人员手动触发，定时入口后续再加
